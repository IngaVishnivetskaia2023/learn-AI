### 1.1 — Agent Architecture

#### Agent Loop
```
┌─────────────────────────────────────────────────────────┐
│                                                          │
│  GENERAL CONCEPT (applies to ALL agent systems):        │
│  ─────────────────────────────────────────────           │
│  "A loop where an AI reasons, acts, observes,           │
│   and repeats until done"                                │
│                                                          │
│  This idea exists in OpenAI agents, LangChain,          │
│  AutoGPT, Google Gemini agents, open-source agents —    │
│  EVERY agent framework has some version of this loop.   │
│                                                          │
│                                                          │
│  CLAUDE-SPECIFIC IMPLEMENTATION (what the exam tests):  │
│  ─────────────────────────────────────────────────────   │
│  The EXACT mechanics of how you implement this loop     │
│  using Claude's Messages API:                           │
│  • stop_reason field (Claude's name for it)             │
│  • tool_use / tool_result content blocks                │
│  • Messages array format                                │
│  • Specific HTTP request/response structure             │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

The exam favours **model-driven approaches** because they flex. 
Claude adapts to situations the developer never mapped out, handles edge cases, and chains tools in orders nobody planned. 
There's one exception worth memorising: 
**when business logic demands deterministic compliance** — financial operations, security checks, regulatory requirements — 
programmatic enforcement overrides that flexibility.
